# 已知限制与后续开发计划

## 1. MVP 已知限制（如实清单）

**解析**
1. OCR 未捆绑：扫描 PDF 只判别并标记 needs_ocr（页级），不产生文本/数值；也不做静默降级。真实扫描件的端到端验证因此尚未覆盖（当前用"渲染重建的图片 PDF" fixture 验证判别与标记路径）。
2. pdfplumber 表检测假阳性：公式对齐/框线会被识别为"表"（语料中单篇最多 104 个）；产出 0 测量时无害，但会拖慢解析（36 页 92.8s）并稀释图区启发式。
3. 第二引擎（pypdfium2）回退页只提供词/文本/图注，不提供表格与内嵌图列表（已在 warnings 中声明）。
4. 版面阅读顺序（双栏跨栏）按词坐标排序近似，复杂版面下 quote 定位得分可能低于阈值 → 记 uncertain 而非入库（诚实但降低召回）。

**抽取**
5. rules-v1 召回有限：真实论文部分金标准召回 50%；下标符号（T₁、kSiC-BN）、未列入模式表的量名（heat flux、specific heat）、复杂句式会漏。表格路径召回高。
6. 量名歧义（σ/ρ/κ/μ/S）标记为 *_ambiguous 而非猜测——需要人工消歧后才可用于数据集（导出中保留原样）。
7. 样品-测量关联启发式（表首列/句内名称匹配）：跨段落指代（"the sample"、"it"）不解析。
8. LLM 适配器仅以注入 caller 完成离线单测（grounding 纪律验证）；未对真实云端点/langextract 实库联调（无 API key 环境）；langextract 适配器按其 1.7.x 公开文档 API 编写。
9. 组成解析停留在原始串（化学式整串保留），不做元素计量分解。

**曲线**
10. 图区检测为启发式（图注+内嵌图 bbox+列宽回退）：多子图（Figure 3a/b/c）区域切分粗糙；无内嵌图（纯矢量绘图）时回退"图注上方 280pt"估计框并留 notes 标记。
11. 未实现自动曲线跟踪（CV 描线）；点取与 WPD 导入均为人工驱动。任何 auto_trace/llm_guess 来源被政策强制 unverified+high_risk。
12. WPD 集成为 CSV 单向交换：CSV 不含像素坐标，叠加验证依赖在 SEELS 内重新校准（WPD 项目 .tar/.json 解析列入路线图）。
13. 曲线点与 measurement 行尚未建立正式关联（数字化结果独立存 curve_points；QC 跨源一致性暂不消费曲线数据）。

**系统**
14. UI 单用户、无认证，服务器绑定 127.0.0.1；并发写靠全局锁串行化（小团队够用，非多租户方案）。
15. 大规模批处理未并行化（逐篇串行；论文级进程池接口上可加）。
16. 当前文本模式面向英文论文；中文论文需扩展模式集与分词处理。
17. 真实论文金标准为"会话代理辅助标注 + PROVISIONAL 标注"，正式基准须领域专家复核并扩充（模板与流程已备好：data/gold/TEMPLATE_real_paper.json）。
18. gold-compare 的"近失诊断"（rel≤0.5 报 VALUE_MISMATCH）可能把不同物理量的邻近值配在一起（评估文档 §3 第 6 项实例），判读需人工。

## 2. 后续开发计划

**P1（近期，1–2 周量级）**
- OCR 引擎接入：实现 DoclingParseEngine（docling，MIT 代码 + RapidOCR/EasyOCR），作为第三 ParseEngine；needs_ocr 页产出带 bbox 的 OCR 文本，证据 source_type=ocr 自动进 C7 高风险人工通道。
- LLM 实测：openai-compat 端点与 langextract（Ollama 本地或云 key）实测，统计 quote 落地率/拒绝率，形成 rules-v1 × LLM 的召回对比报告（金标准流程复用）。
- 表格增强：多行表头合并、单位列继承、跨页表格续接；表假阳性过滤（单元格数值密度启发）。
- 曲线→测量关联：curve_id 可挂到 measurement（source_type=curve），C5 跨源一致性纳入曲线数据。
- WPD 项目文件（.json/.tar）解析适配器：直接回收像素坐标，免去二次校准。

**P2（中期）**
- MinerU 引擎适配（扫描/复杂版面；许可条款合规审查先行）；docling chart2csv 作为 auto_trace 来源接入曲线层（永不自动 verified）。
- 批处理并行化（论文级进程池 + 任务清单/断点续跑报表）；解析缓存指纹（输入哈希→产物哈希）进 PROVENANCE。
- 专家标注工作流：UI 内金标准标注模式（选中区域→生成 gold item），双标注者一致性统计。
- 跨论文数据集治理：样品全局去重（组成指纹）、量-单位本体扩展、ML 数据集版本化导出。

**P3（远期）**
- docling-graph 式证据知识图谱（论文-样品-测量-条件实体关系 + provenance 台账），支撑跨文献检索与矛盾发现。
- 主动学习闭环：人工驳回/修改样本回流为规则与 LLM few-shot 示例库。
- 曲线自动跟踪（CV）作为 auto_trace 候选源，配合叠加验证与人工抽检。

## 3. 明确不做（本系统边界）

- 不做"无人值守全自动入库"：正式数据必须过人工复核（accepted）或至少带完整证据链与 QC 通过标记（candidate）。
- 不把 LLM 置信度、模型自评分写入任何"正确性"字段。
- 不修改、不迁移、不覆盖原始 PDF；派生物一律进 data/work。
- 第一版不引入通用 Agent 框架/消息队列/微服务（复杂度与目标不匹配）。
